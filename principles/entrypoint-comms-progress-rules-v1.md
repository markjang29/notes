## 1. 진입점 — 모든 접속은 43.201.34.144 하나

- 모든 접속은 **43.201.34.144(엣지)** 에서 **Tailscale로 홈서버(duradev)** 에 연계된다.
- 다른 진입 주소(구 8GB `13.125.131.126` 등)는 폐기다 — **사용·안내·문서 기록·시도 전부 금지.**
- 모든 신규 개발은 두 단계를 함께 고려한다:
  - **1차** — 홈 사이트(duradev)와 연결 가능하게 만든다. 엣지 경로는 항상 홈을 가리킨다.
  - **2차** — 원사이트 통합 본(Spring + React, matrix-studio-spring)에 흡수 가능하게 만든다.

## 2. 정보 갱신 의무 — 관제·사칙·정책센터 대조

각 봇은 기동 시와 주기적으로 다음을 한다:

1. **주소 확인**: 관제 `43.201.34.144/hub` · 정책센터 `43.201.34.144/policies` · 사칙 정본(notes Git).
2. **자기 정보 업데이트**: 엔진·모델·담당·역할·상태를 원장(roster)과 관제에 최신으로 반영한다.
3. **앞으로의 통신 반영**: 자신이 쓸 폴링 주소·메시지 창구·이사님 공통지시사항을 자기 설정과 문맥에
   업데이트한다. 주소는 하드코딩하지 않고 정책센터에서 읽어 쓴다.

## 3. 폴링·스케줄링 점검 의무

- 폴링·스케줄링은 **전부 리스트업** 한다: 무엇이 · 어디를 · 몇 분 주기로.
- 점검 2항목:
  - **부하**: CPU·요청 수가 무시할 수준인가.
  - **토큰**: 폴링 과정에서 LLM 토큰을 쓰지 않는가 — 폴링 자체는 항상 토큰 0이어야 한다.
- 낭비·부하를 발견하면 즉시 조정하고 그 결과를 관제에 기록한다.

## 4. 대화 규칙 (Telegram 운용)

- **큐시작 / 큐끝**: 이사님이 "큐시작"이라 보내면 **말하지 않고 수신만 한다.** "큐끝"이라 하면
  그때 다 듣고 한 번에 답한다. (긴 메시지를 여러 건 나눠 보낼 때 잘림·끼어들기 방지)
- **긴 답변 분할**: 파일로 잘려서 나갈 것 같은 답은 파일 대신 **텍스트를 나눠서** 말한다.
- **eli5**: 답 끝에 eli5(쉬운 말 풀이)를 붙인다.
- **표 금지**: 텔레그램은 마크다운 표를 못 본다 — **리스트로 풀거나 임시 웹 페이지·이미지**로 보여준다.
- **진행 보고(n/20)**: 일을 시키면 "1/20" 식으로 단계와 변경점을 보여주고, **이사님 확인을 받은 뒤**
  다음 단계로 진행한다. 확인 없이 다음 단계로 가지 않는다.
- **모델·컨텍스트 상시 보고**: 항상 자신의 모델과 컨텍스트 사용량을 답장에 포함한다.
  사용 모델이 **LMM gateway**인지 **z.ai API**인지 구분하여 답장한다. 모델 변경 요청,
  사용 API 변경 요청에 대응할 수 있도록 숙지한다.
- **규칙 정본 commit 표기**: 항상 본인이 숙지한 규칙 정본(이 문서)의 **마지막 commit**을
  답장에 표기한다. 갱신 요청 시 재독 후 갱신하여 답한다.
- **관제 주시**: 관제 사이트(43.201.34.144/governance, /hub)의 공지와 자기 앞 메시지를
  상시 주시한다.
