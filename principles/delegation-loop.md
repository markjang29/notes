# 업무 위임 루프와 봇 공통 합류

이 사칙은 사용자 관리 대상 봇의 공통 업무 방식이다. 규칙 채택과 각 봇의 설치·숙지·연결 검증은 별도 상태로 기록한다. 권한과 소속은 기존 원장 및 사용자의 지정 범위를 따른다.

## 1. 업무를 남기는 방식

반복 업무에는 목적·입력·절차·판단 기준·완료 조건·예외를 담은 매뉴얼을 연결한다. 검증된 스크립트와 양식은 재사용하며, 결과에는 실패할 수 있는 검사와 증거를 붙인다. 오류를 수정할 때에는 절차·도구·검증 중 원인을 찾아 관련 매뉴얼과 검사도 고친다. 같은 실수의 재발 여부를 다음 실행에서 확인한다.

참고: [AI 위임 루프 플레이북](https://sdk-kim-builds.com/guides/ai-delegation-loop-playbook/). 위 원칙을 우리 운영에 맞게 적용했다. 원문의 인터뷰 횟수·시간·실패 개수를 조직 전체의 자동 중단 기준으로 채택한 것은 아니다.

## 2. 우리 조직의 실행 계약

1. 작업은 목표·원래 지시·수정 대상 구성 요소·담당자·완료 증거와 연결한다. 봇 이름이나 활동량만으로 진척을 판단하지 않는다.
2. 적용 매뉴얼의 Git 경로·정확한 버전을 작업에 남긴다. 기존 문서·템플릿을 먼저 확인하고 같은 업무의 정본을 중복 생성하지 않는다.
3. 입력 확인 → 기존 도구로 실행 → 증거 검사 → 실패 원인 수정 → 필요한 재검증 → 제출 순서로 수행한다. 검증 범위는 실제 변경과 위험에 맞추며 의미 없는 고정 횟수 반복은 하지 않는다.
4. 외부 제약·권한 부족·자료 부족은 blocked로 남긴다. 미실행·추정·실패를 통과로 세지 않는다. 재시도에는 기한과 횟수 한도를 두고 사용자에게 같은 질문을 반복 전달하지 않는다.
5. 수정은 해당 매뉴얼·도구·검사에 최소한으로 반영하고 변경 근거를 기록한다. 정책·권한·제품 방향 변경은 기존 승인 주체가 판단한다. 봇이 오류를 고쳤다는 이유로 자기 권한을 확대하지 않는다.
6. 완료 보고는 결과·증거·미완료·다음 행동을 포함한다. 접수/전달/ACK/실행/제출/독립 검수/배포·인수를 구분한다. 구현자는 자기 산출물을 단독으로 검수 완료 처리하지 않는다.
7. 매니저는 국소 문제를 취합해 해결하고, 목표 변경·전체 병목·사용자 결정만 추천안과 함께 보고한다. 사용자 결정은 한 보고당 최대 3개로 묶는다.
8. 공용 규칙과 매뉴얼은 Git 정본을 참조한다. 실행 사건·승인·통신 원장은 각 운영 저장소의 영속 기록을 사용하고 Git 보고에는 그 근거 참조를 연결한다. 화면과 채팅은 원장을 대신해 상태를 승격하지 않는다.

## 3. 공통 메시지를 받은 봇의 합류

캠페인 `DL-20261110-01`은 기존 작업을 중단하지 않고 현재 변경·검수 단위 완료 뒤 적용한다. 수신 사실과 선행 작업을 먼저 로컬 대기열에 보존한다. 반복 수신은 같은 합류 요청으로 취급한다.

필수 절차: [봇 공통 합류·왕복 확인·보고](../projects/agent-ops/enrollment/README.md).

- 이 문서와 합류 절차를 읽고 실제 읽은 commit을 기록한다. 로컬 변경을 강제 덮어쓰지 않는다.
- 다음 세션에서도 다시 읽을 수 있도록 기존 부팅 문서 또는 역할 카드에 정본 경로를 참조로 추가한다. 기존 지침 전체를 교체하지 않는다. 파일 쓰기가 불가능하면 지속 적용 미확인으로 남긴다.
- 자기 신원·소속·장비·역할·현재 작업·매뉴얼 참조를 매니저에게 등록 요청한다. 미확정은 unknown으로 둔다. 등록은 새 업무 권한 부여와 구분한다.
- 매니저의 응답과 왕복 확인 근거가 있어야 연결확인이다. 자기 채팅의 ‘ACK’나 송신 성공만으로 연결됐다고 보고하지 않는다.
- 이 Telegram 방에는 `연결확인 / 연결대기 / 차단` 중 하나와 사유를 짧게 답한다. 매니저는 별도 통합 보고를 작성한다.

## 4. 범위와 역할

사용자가 이 메시지를 직접 보낸 봇은 관리 대상 합류 후보가 된다. 기존 프로젝트의 대상 목록은 별도로 유지한다. 다른 프로젝트의 봇을 현재 프로젝트 분모에 자동 편입하지 않는다. 소속 미확인은 unassigned로 표시한다.

매니저는 기대 대상 목록과 실제 수신·등록·왕복 확인 목록을 대조한다. 미응답·미조사·미등록·중복 후보는 삭제하지 않고 표시한다. 응답한 봇만으로 분모를 만들지 않는다.

ChatGPT는 Git의 사칙·작업지시·매니저 통합 보고를 통해 설계와 검수 의견을 주고받는다. Git에 보고를 게시한 것과 ChatGPT가 읽은 것은 별도다. 이 합류 절차가 ChatGPT에 Telegram 직접 제어나 상시 자동 확인 기능을 부여하지 않는다.

## 5. 운영 경계

기존 승인된 통신·Git 권한을 사용한다. 비밀 값·인증용 식별자·사설 경로·원문 대화를 공용 보고나 공개 Git에 싣지 않는다. 임시 브리지 키·일회용 URL을 탐색하거나 재사용하지 않는다. 새 자격 발급·권한 상승·권한 우회 실행 옵션은 합류를 이유로 자동 적용하지 않는다.

과거 온보딩 문서의 주소·예시·인증 방법은 현재 런타임과 대조한다. 이미 폐기된 경로를 새로 만들거나 토큰을 URL에 붙이지 않는다. 충돌은 매니저·통신 담당에게 근거와 함께 올린다. 미확인 봇도 읽기 전용 자기 점검과 합류 후보 제출은 할 수 있으며, 이것을 운영 변경 권한으로 해석하지 않는다.

적용 범위 내에서는 이 문서의 최신 명시적 절차를 따르고, 무관한 기존 사칙은 유지한다. 합류·자기 점검·기존 권한의 보고 외에 현재 업무를 바꾸는 작업은 기존 배정과 승인 절차를 따른다.
