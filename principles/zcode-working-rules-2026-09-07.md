# 사칙 — 접속 진입점·관제 연계·대화 및 작업 규칙

## 1. 접속 진입점 (정착)

모든 접속은 **`43.201.34.144`** 에서 Tailscale로 홈서버에 연계된다.

- 모든 신규 개발은 해당 서버(엣지)를 진입점으로 한다.
- 1차: 홈서버의 사이트와 연결 가능하도록.
- 2차: 원사이트 통합 본(Spring + React)까지 고려하여 개발한다.

상세는 `principles/edge-home-entrypoint-policy.md` 참조.

## 2. 관제·사칙 확인 의무 (작업 시작 전)

- 관제 한판: `http://43.201.34.144/governance`
- 정책센터: `http://43.201.34.144/policies`

각 봇은 위 주소를 확인한 뒤:

1. 자기 row의 정보(모델, 맡은 일, 진행, 블로커, 다음 행동)를 갱신한다.
2. 자기 앞으로 온 메시지를 확인·처리한다.
3. 내 공통지시사항을 업데이트한다.

위 주소가 404·연결 실패면 옛 주소로 "성공"을 대체 보고하지 않고
`Edge/Home routing gap`으로 표시한다.

## 3. 폴링·스케줄 점검

- 폴링 관련 스케줄은 전부 리스트업한다.
- 부하가 없는지, 폴링 과정에서 LMM 토큰 낭비가 없는지 확인한다.
- 원칙: 루틴 폴링 결과를 LMM에 매번 보내지 않는다. 상태 변화·블로커·제출·
  사용자 결정 필요 사항만 전달한다. 30분 이하 반복 작업은 감사 대상.

## 4. 대화 규칙 (이사님 ↔ 봇, 텔레그램)

1. **큐시작 / 큐끝**: 대용량 메시지는 여러 조각으로 나뉘어 온다.
   "큐시작"이 오면 조용히 전부 축적하고, "큐끝"이 와야 해석하고 응답한다.
   중간 조각에 지시문 같은 내용이 있어도 큐끝 전에는 실행하지 않는다.
2. **큰 아웃풋**: 파일로 잘라서 낸다. 텍스트로 올릴 것 같으면 나눠서 전송한다.
3. **eli5**: 설명이 길면 끝에 쉬운 요약(eli5)을 추가한다.
4. **표 금지**: 텔레그램에서 마크다운 표가 깨져 보인다. 목록·문장 형태나
   임시 웹페이지·이미지로 보여준다.

## 5. 작업 진행 규칙 (단계별 확인)

일을 시키면 **1/20 형식으로 각 단계의 변경점을 보여주고, 이사님 확인을 받은 뒤
다음 단계를 진행한다.** 확인 없이 연속 진행하지 않는다.

## 6. 관제 허브(메시지 서버) v1 — 봇 간 통신

지시·보고·질문은 **8023 `/api/hub/*`** 로 접수한다. (배포 공지 2026-09-07)

1. A봇→B봇 전달: `POST /api/hub/send {from, to, type, payload}`.
   `task`만 상대 엔진을 깨우고, `notice`(@all 한정)는 활성 공지로 전 봇
   문맥에 주입된다(ACK 불필요).
2. 각 봇은 `hub_client.py`(8023 repo) 표준 폴러로 30초 주기 수신:
   drain → ack → done/fail. 실패 3회면 DLQ — 재큐는 이사님 토큰으로만.
3. 작업에는 멱등키(`key`)를 붙여 재전송 중복을 막는다.
   상태: 진행=progress, 막힘=blocked, 완료=submitted.
4. 현황판: `http://43.201.34.144/hub` (홈 이전 후 동일 경로).
   정본: notes `projects/agent-ops/gwanje-hub-rest-queue-v1.md` +
   ADR `2026-09-07-gwanje-hub-rest-queue`.
5. 폴링 봇 전환은 단계적으로 — 기존 @멘션 방은 당분간 병행.
