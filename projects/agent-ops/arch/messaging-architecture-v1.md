## 0. 설계 원칙 (SECS/GEM 유비)

1. **시스템은 독립** — 각 서비스는 자기 포트·자기 DB. 통합 금지. (SECS: 장비와 호스트는 별개)
2. **메시지만 표준** — 계약(7필드+토픽)만 지키면 구현 언어·프레임워크 무관. (SECS: SML 표준)
3. **모든 계약은 원장 남김** — 누가 무엇을 언제 보냈는지 8024 nats_delivery(persist)가 증적. (SECS: GEM 리포트+트랜잭션 로그)

## 1. 매개체 (broker) — 결정: NATS 단일, Kafka 아님

| 항목 | 판정 | 근거 |
|---|---|---|
| **NATS** (가동 중, 4222) | ✅ 채택·확장 | 이미 설치·98봇이 운영·Core+JetStream 지원·브라이언-라이트(53프로세스급 규모에 과적합) |
| Kafka | ❌ 보류 | 20서비스 규모(초당 메시지 수십 건)에 과투자: 주키퍼/KRaft·파티션 운영 비용 > 이득. 초당 수천건 이상으로 커질 때 재평가 |
| RabbitMQ/MQTT | ❌ 보류 | 규모 대비 구조 복잡. 등록제 승인 필요 |

- JetStream: **message 종류 중 notice·task만 유지(7일, replay)** — ACK·progress는 at-most-once(원장이 증적이므로 유선 재전송 불필요)
- 단일 NATS 서버 장애 시: 사칙 §7 규칙(8024가 자동감지→이사님 통보) + 재접속 후 미수신 자동회수(보존 7일)

## 2. 메시지 종류 (계약 — 사칙 7종 → 12종 확정)

### 2-1. 봇↔봇 (현행, 시행 중) — 7종
`task · notice · ack · progress · blocked · submitted · review` — 8024 NatsLogController TYPES에 코드로 고정. 변경은 사칙 개정만.

### 2-2. 시스템↔시스템 (신규, 이번 define) — 5종
| type | 의미 | 예 | 응답 계약 |
|---|---|---|---|
| `heartbeat` | 서비스 살아있음(30초 주기) | 8023→NATS | 미수신 3회 → 8024가 이사님 텔레그램 통보(사칙 §7) |
| `state` | 상태 변화 통보 | 8025→8024: "BD 흡수 완료" | 응답 없음, 원장만 |
| `data_sync` | 데이터 동기화(증분) | 8026→8023: 소설 원문 색인 갱신 | 수신측이 `ack` (7필드) |
| `request` | 동기 요청/응답 패턴 | 8018→8024: "현황 원장 줘" | 상대는 `reply`(아래) |
| `reply` | request에 대한 응답 | 8024→8018: 결과 | 원장-상호 연계 |

- 공통 헤더: 기존 7필드(id·ts·subject·from·to·text·payload) + **version**(스키마 버전, 1~) + **ref**(근거) — 토픽 3종은 불변(`bot.msg.*`·`notice.broadcast`·`bot.ack.*`) + 시스템간 `svc.msg.<fromSvc>.<toSvc>` 1종 신설

## 3. 흐름 (flow — 3패턴만)

```
[패턴 A: 발행-구독 (fanout)]      notice·heartbeat
  8024/서비스 ──publish──▶ NATS ──▶ 구독자 전원 + 8024 원장

[패턴 B: 큐 (work queue)]        task·data_sync
  발신 ──▶ NATS(subject: bot.msg.A.B | svc.msg.X.Y) ──▶ 1개 수신자(점유) ──▶ 처리 ──▶ ack
  장애 시: JetStream 7일 보존 → 재접속 자동회수 (사칙 §7)

[패턴 C: 요청-응답 (req-rep)]    request·reply
  발신 ──▶ request (reply-to 토픽 자동부여) ──▶ 수신 ──▶ reply (NATS inbox 메커니즘) ──▶ 원장
  타임아웃 30초 — 응답 없으면 blocked
```

- 봇↔봇 = B패턴(task)·A패턴(notice). 시스템↔시스템 = 3패턴 전부.
- **모든 흐름의 끝에 원장**(8024 persist) — "누가 언제 누구에게 무엇을, 배달됐나, 확인했나" 증적 없는 메시지는 규칙 위반.

- Kafka 등 신규 브로커 도입은 본 문서 개정으로만 (임의 설치 금지)
- 서비스 간 직접 DB·내부API 참조 금지 (이사님 09-22 지시 "분리운영"의 실행문)

## 6. ELI5

지금까지는 사람(봇)들끼리 쓰는 공중파전화(8024 comm)를 정했다. 이번엔 기계(서비스)들끼리 쓰는
전화규격을 정한다: 종류(무슨 말이 있나: 연락·보고·요청·답장), 흐름(1:대 다수 말하거나, 1:1 일
맡기거나, 질문-답하거나 — 3가지뿐), 매개체(전화국: NATS, 이미 서버에 있음 — 새로 짓지 않음).
모든 통화는 8024에 녹음되고, 연락두절 3번이면 아버지 폰에 온다.
