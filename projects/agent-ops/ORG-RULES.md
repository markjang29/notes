## 4. 관제 허브(메시지 서버) v1 — REST 큐 [배포·이사님 09-07 지시]

- 봇 간 통신이 REST 큐로 바뀌었다. 지시·보고·질문은 **8023 `/api/hub/*`**로 접수.
- **A봇→B봇 전달**: `POST /api/hub/send` `{from, to, type, payload}`
  - `task`만 상대 엔진을 깨운다.
  - `notice`(@all 한정)는 활성 공지로 전 봇 문맥 주입(ACK 불필요).
- **수신**: 각 봇은 `hub_client.py`(8023 repo) 표준 폴러로 **30초 주기** — drain → ack → done/fail.
  - 실패 3회면 못 처리함(DLQ). 재큐는 이사님 토큰으로.
- **멱등키(key)**를 작업에 붙여 재전송 중복을 막는다. 상태: 진행=`progress`, 막힘=`blocked`, 완료=`submitted`.
- **현황판**: http://43.201.34.144/hub (홈 이전 후 동일 경로).
- **정본**: notes `projects/agent-ops/gwanje-hub-rest-queue-v1.md` + ADR `2026-09-07-gwanje-hub-rest-queue`.
- 폴링 봇 전환은 단계적 — 기존 @멘션 방도 당분간 병행.
- **오너(이사님 09-08 지시)**: `heav_lnx_codex_dev_1_bot`(dev1) — 허브(8023)·관제 현황판 운영 총괄.
  원사이트 통합 시 `/control` 코너로 흡수 예정.
- **이관 상태(매니저 09-08 실측)**: 서비스는 duradev:8023 가동 완료(200). 단 **큐 데이터는 미이관** —
  AWS 9건 대기·2건 done vs duradev 0건. 엣지 `/hub` upstream은 아직 AWS(13.125) —
  **AWS 큐 소진 확인 후** upstream 1행 교체(100.109.91.0:8023)로 스위치오버. 오너 dev1이 집행.

## 5. 대화·보고 규칙 (이사님과의 소통)

- **큐 모드**: "큐시작"을 보내면 여러 통으로 잘려 오는 메시지를 전부 수신만 하고,
  끝에 "큐끝"이 오면 그때 한 번에 답한다(중간에 말하지 않는다).
- **아웃풋 규칙**: 텍스트가 잘릴 것 같으면 ①파일로 보내거나 ②여러 통으로 나눠 말한다.
- **eli5 첨부**: 긴 산출물 끝에는 eli5 요약을 덧붙인다.
- **표 금지**: 텔레그램에서 마크다운 표를 못 보므로 ①불릿 ②임시 웹페이지 ③이미지로 대체한다.
- **단계 게이트·진행률**: 일을 시키면 **"1/20" 식으로 진행률을 표시**하고, 각 단계의 변경점을
  보여주어 이사님 확인을 받은 뒤 다음 단계를 진행한다.

## 6. 상시 답장 규칙 (모든 답장에 포함) [09-07 추가 · 09-08 신규 봇 자체 추가분 통합]

- **항상 자신의 모델과 컨텍스트 사용량을 답장에 표기한다.** — 실측(`~/scripts/context-meter.sh`) 기준, 추정 금지.
- **사용 경로 구분**: 사용 모델이 **LLM Gateway**인지 **z.ai API**인지 구분하여 표기한다.
- **모델 변경 요청·API 사용 요청**에 즉시 대응할 수 있도록 방법을 숙지해 둔다 — 8018 `/fleet`(봇별 모델·전역 매핑·provider 전환)로 즉시 전환 가능 상태를 유지한다.
- **항상 본인이 숙지한 규칙 정본의 마지막 commit을 답장에 표기**하고, 갱신 요청 시 갱신한다.
- **관제 사이트의 공지와 메시지를 주시(모니터링)한다.** — 공지는 허브 notice 주입으로 수신하고, 자체 폴링은 새로 만들지 않는다.
