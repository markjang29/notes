# 보고 가이드라인 v1

> 이사님 09-30: "보고하는 것도 차근차근, 장황하고 불필요한 보고 안 하도록." 참고 예시(네이버 블로그)는
> 접근 차단으로 열람 못 함 — 이 문서는 "차근차근·비장황"이라는 지시 자체를 규칙으로 옮긴 것.
> 예시 글의 문체를 반영하려면 링크 대신 캡처나 텍스트 붙여넣기로 재확인 필요.

## 1. 형식 규칙 (모든 봇 보고 공통)

1. **결론 먼저, 한 줄.** 무엇이 됐다/안 됐다/막혔다를 첫 줄에. 배경 설명을 앞세우지 않는다.
2. **한 단계 = 한 문장.** 여러 조치를 했으면 번호 목록으로 나열하되, 각 항목은 1문장. 문단으로 풀어쓰지 않는다.
3. **증거는 값 하나로.** "성공했다"가 아니라 검증 명령·출력 1줄(`systemctl is-active X` → `active`). 로그 전체·표 전체를 붙여넣지 않는다.
4. **모르는 것은 "검증필요"로 명시.** 추정을 확정처럼 쓰지 않는다.
5. **다음 행동이 있으면 마지막에 1줄.** 없으면 안 쓴다("계속 지켜보겠습니다" 같은 상투구 금지).
6. **분량 상한**: 정기 보고는 5줄 이내, 이슈 보고는 10줄 이내. 초과하면 근거는 파일·커밋 링크로 돌리고 본문은 요약만.
7. **금지**: 비유·수사("드디어", "완벽하게"), 감정 표현, 같은 사실 반복, 목차·서론.

## 2. 봇별 보고 채널과 빈도 (일원화 — §3 지휘체계와 연결)

| 보고 종류 | 받는 사람 | 채널(단일) | 빈도 |
|---|---|---|---|
| 작업 완료/실패 | 담당 매니저 | 8024 원장(type:progress) | 이벤트 발생 시 1회 |
| 게이트 판정 필요 | 이사님 | 승인보드(8005) 카드 | 게이트 진입 시 1회 |
| 일일 현황 | 이사님 | 매니저가 §1 규칙으로 취합 1건 발송 | 1일 1회(09시) |
| 장애·블로커 | 매니저→(48h 미해결시)이사님 | 8024 원장 + 텔레그램 | 즉시 |

- 봇이 이사님께 직접 텔레그램을 보내는 경우는 **장애·블로커(에스컬레이션)** 와 **명시적으로 요청받은 산출물** 뿐. 나머지는 매니저가 취합해 하루 1건으로 압축한다(스팸 방지, agenda.py의 원래 취지와 동일).
- 취합 보고도 §1 규칙을 따른다 — 매니저가 취합했다고 분량 상한이 풀리는 게 아니다.

## 3. 지휘체계 (역할·승인선)

```
이사님 (최종 승인자·요구 발신)
  └─ 매니저 (heav_lnx_bot) — 파이프라인 전체 감독, 티켓 발령, 일일 보고 취합, 에스컬레이션 1차 판단
       ├─ 감사(audit_bot) — 교차 검수, 지휘선 아님(누구에게도 지시하지 않음, 판정만 발행)
       ├─ 테스터(97 gmwin_codex_bot) — 게이트 검증만, 상태 전이 권한 없음(권고만)
       └─ 실행 봇 (01~04, 95~99, scenario/rpg 등) — 담당 단계 실행, 완료/실패를 8024로만 보고
```

- **승인 종류는 2가지만**: 설계승인(매니저 위임 가능) · 배포승인(이사님 전용, 위임 불가).
- **자동발령 메시지는 반드시 서비스 신원**(`taiga-bridge`)으로 나간다. "이사님" 명의 자동 발령 금지 — 이사님 발언=요구사항이라는 대화규칙과 충돌하기 때문([[2026-09-30-system-improvement-review]] G5 참조).
- **감사·테스터는 지휘선에 없다.** 판정을 내리지만 누구에게도 작업을 지시하지 않는다 — 판정과 지시 권한을 분리해 게이트가 스스로 통과시키는 사고(G2)를 구조적으로 막는다.
- **실행 봇은 서로 직접 지시하지 않는다.** 단계 간 인계는 8024 메시지(type:task)로만, 봇 대 봇 텔레그램 지시 금지 — 지휘선이 매니저 하나로 유지되게 한다.

## 4. 통신 채널 일원화 방향 (단계적 폐기)

현재 3중(8023 회의방 REST · 8026 hub-spring · 8024 NATS/원장) + 텔레그램 산발 발송이 공존한다.
방향: **8024를 유일한 증적 채널로, 텔레그램은 "이사님이 읽는 알림"으로만 남긴다.**

1. 신규 자동 발령·게이트 알림은 8024로만 (즉시 적용 가능, 코드 변경 필요 — [[2026-09-30-system-improvement-review]] N5/G5 티켓).
2. 8023 회의방은 사람이 직접 대화하는 경우로 축소, 자동화 스크립트의 송신 대상에서 제외.
3. 8026 hub-spring은 실제 점유자(추정 nai-queue)와 문서상 주(主)가 다르므로, 이사님 결정(N5) 전까지 신규 연동 금지.
4. 텔레그램은 매니저 취합 알림 + 장애 에스컬레이션 전용. 실행 봇의 개별 산발 발송은 §2 표로 대체.

이 순서는 시스템을 직접 바꾸지 않고 방향만 기록한 것 — 실제 코드/설정 변경은 각 항목이 가리키는 review 문서의 티켓(P0=이사님 승인, P1=매니저 승인)을 통해 진행한다.
