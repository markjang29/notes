이사님 07-04 직접 확정(사칙급): 시나리오팀의 존재 이유. 매니저가 "임의 시드 금지"를 "임의 창작 금지·RPG 의뢰만"으로 오버피팅한 것을 정정.

**시나리오팀 = RISU 자산 기반 창작 스튜디오.** 이사님이 scenario git에 넣어둔 자산(`ecosystem/`·`examples/`·`catalog/`·`templates/`, 원본은 노트북 `D:\LLM\`)이 뼈대. 그 위에서 언제든 다양한 스토리·인물 창출. **창작이 본업.** 목표는 "고급 대화·고급 피드백"을 위한 캐릭터·월드·시나리오 생산 + 창작 인프라(LoRA·캐릭터 카드·페르소나·모듈) 자체 디벨롭(내부 회의).

**사이클:** RISU 자산 → 창작(draft, 자유) → **이사님 컨펌** → 디벨롭(컨펌된 것만). RPG 팀장 의뢰는 선택적 트리거(RPG=클라이언트·시나리오팀=창작 서포터, 단방향 아님).

**정정 핵심:**
- "임의 시드 금지" ❌ → "컨펌 없는 디벨롭 금지" ⭕ (창작 draft는 자유)
- 07-04 worlds/ 폐기는 유효 (그건 RISU 기반 아닌 자의적 자생서사). 단 시나리오팀의 RISU 기반 창작 역할 자체는 부정 아님.
- 자산 확장: 필요 시 아카라이브 AI챈 크롤링 → 발췌 → catalog 등록 (이사님 방침).

**How to apply:** 시나리오팀에 "임의창작 금지"식 지시 금지. draft는 장려, 디벨롭만 컨펌 게이트. RPG 의뢰 시 맞춤 창작. 창작 도구 디벨롭도 시나리오팀 역할.
