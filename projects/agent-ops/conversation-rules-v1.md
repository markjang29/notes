# 대화·소통 규칙 v1 (전 봇 공통)

- 발효: 2026-09-07 (이사님 텔레그램 직접 지시)
- 대상: 모든 봇·에이전트 — 관제 허브(메시지 서버) v1과 함께 적용
- 위치: notes projects/agent-ops/conversation-rules-v1.md (정본, 각 봇 온보딩 참조)

## 1. 접속·진입점 원칙

- 모든 접속은 이제 엣지 `43.201.34.144`에서 tailscale로 홈서버(duradev)에 연계된다.
- 모든 신규 개발은 해당 서버(엣지 → 홈서버)를 진입점으로 개발한다.
  - 1차: 홈의 사이트와 연결 가능하도록 (경로 통합, `/사이트명/` 방식)
  - 2차: 원사이트 통합 본(스프링+리액트)까지 전제로 설계한다.
- 구 주소(13.125.131.126 등) 개별 포트는 신규 진입점으로 쓰지 않는다.
  전환 기간 병행 서빙만 허용.

## 2. 자기 정보 갱신 의무

관제·사칙·정책센터 주소를 확인한 뒤 각 봇은:
- 자신의 설정·문서에 기록된 주소를 업데이트한다.
- 앞으로 보낼 메시지(안내·링크)에 새 주소를 반영한다.
- 이사님 공통지시사항을 최신으로 반영한다.

## 3. 폴링·스케줄링 감사

- 폴링과 관련된 스케줄링은 전부 리스트업한다.
- 각 항목마다 두 가지를 확인한다.
  - 서버 부하가 없는지
  - 폴링 과정에서 LLM 토큰 낭비가 없는지
- 응답할 일 없는 폴링(불필요한 엔진 기동)은 이벤트 방식 전환 또는 주기 연장으로 정리한다.

## 4. 큐 모드 (긴 입력 수집)

- 이사님이 **"큐시작"**이라고 보내면:
  - 잘림 방지를 위해 여러 개 메시지로 나눠 보내는 중이다.
  - **다 받을 때까지 아무 응답도 하지 않고 수집만 한다** (짧은 확인·중간 요약 금지).
- 이사님이 **"큐끝"**이라고 하면 그때 비로소 전부 다 듣고 답한다.

## 5. 출력 방식 (텔레그램 기준)

- 출력이 파일로 첨부되어 잘릴 것 같은 길이면, 파일 대신 텍스트를 나눠서 말한다.
- 설명 끝에 **ELI5(쉬운 말 요약)**를 덧붙인다.
- 텔레그램은 마크다운 표를 렌더링하지 못한다 — 표 대신:
  - 들여쓰기 리스트로 풀어서 보여주거나
  - 임시 웹 페이지(사이트에 올리고 링크) 또는
  - 이미지(표를 그려 전송)로 보여준다.

## 6. 단계별 진행 (확인 게이트)

- 일을 시키면 진행 단계를 `1/20` 식으로 번호를 매겨 보고한다.
- 각 단계의 **변경점(무엇이 바뀌는지)**을 보여주고 이사님 확인을 받은 뒤 다음 단계를 진행한다.

## 7. 관제 허브(메시지 서버) v1 — 배포·이사님 09-07 지시

봇간 통신이 REST 큐로 바뀌었다.

- 지시·보고·질문은 8023 `/api/hub/*`로 접수한다.
- A봇→B봇 전달: `POST /api/hub/send {from, to, type, payload}`
  - `type=task`만 상대 엔진을 깨운다.
  - `type=notice`(@all 한정)는 활성 공지로 등록되어 전 봇 문맥에 주입된다 (ACK 불필요).
- 각 봇은 `hub_client.py`(8023 repo) 표준 폴러로 30초 주기 수신:
  `drain → ack → done/fail`
  - 실패 3회면 못 처리함(DLQ) — 재큐는 이사님 토큰으로만.
- 작업에는 멱등키(`key`)를 붙여 재전송 중복을 막는다.
  - 진행=`progress`, 막힘=`blocked`, 완료=`submitted`.
- 현황판: `http://43.201.34.144/hub` (홈 이전 후 동일 경로).
- 정본: notes `projects/agent-ops/gwanje-hub-rest-queue-v1.md` +
  ADR `2026-09-07-gwanje-hub-rest-queue`.
- 폴링 봇 전환은 단계적으로 — 기존 @멘션 방식도 당분간 병행된다.
