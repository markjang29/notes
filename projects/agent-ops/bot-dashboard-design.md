# 봇 대시보드 사이트 설계서 (v1, 2026-09-02 — 이사님 지시)

> 목적: 봇 조직의 역할·실적·토큰·모델을 한 화면에서 보고, 모델은 화면에서 바꿀 수 있게.
> 상태: **설계 완료 → 검수 대기(감사)**. 구현은 검수 통과 후.

## 1. 서비스 개요

- 이름: **봇 대시보드** (관제 조직 현황판) · 포트 **8025** (8023 회의방·8024 spring 다음 빈 포트)
- repo: `~/projects/bot-dashboard` (신설, FastAPI + 단일 페이지)
- 홈 연동: `~/projects/matrix-home/main.py` SITES에 8025 추가 (사이트맵·홈 카드)
- 기술: FastAPI + 서버 렌더 HTML + **인라인 SVG 차트**(외부 CDN 금지 — 토큰0·사내망 원칙 유지)

## 2. 화면 구성 (4패널)

1. **위치별 봇 카드** — awslnx·firewin·gmwin·gmlnx·asus 그룹. 봇별로 역할·상태·담당 프로젝트·
   회의방 입장 여부(⏳/정식). 데이터: notes org-structure(위치 배치 정본) + meeting-room /api/bots
2. **토큰 트렌드** — 일자별 총 토큰 + 모델별 누적 영역차트(최근 30일).
   데이터: ① zai-fallback-proxy.log `REQ-SUMMARY`(총 토큰·모델·시각 — 이미 실측 존재)
   ② 회의방 엔진 호출 신설 로그 `usage-log.jsonl` (server.py가 봇별 호출마다
   {ts, bot, model, tokens} 기록 — 봇별 토큰 가시화의 핵심 보강)
3. **사용 모델 (설정가능)** — 봇별 현재 모델·API 경로 표(/status 패턴 재사용, 채팅ID 마스킹 유지).
   **변경**: 행별 "변경" → 모델 입력 → `POST /api/model {bot, model}` — **ACCESS_TOKEN(이사님)
   전용**. 서버가 bot_settings.json의 models를 갱신하고 변경 이벤트를 로그에 남김.
   ⚠ 반영 경로 주의(검수 포인트): ccserver가 bot_settings를 메모리에 캐시 중일 수 있음 —
   즉시 반영이 안 되면 봇 서버 재적용 절차를 UI에 명시
4. **실적 타임라인** — 봇별 최근 보고·완료 카드. 데이터: 회의방 room.jsonl(봇 발언) +
   notes work-queue 처리 기록 링크

## 3. 데이터 원칙

- 봇을 깨우지 않는다 — 전부 파일·설정 실측(LLM 호출 0, 토큰 0)
- 토큰·API키·채팅ID 표시 금지(마스킹 규칙 유지). 모델 변경 API는 이사님 토큰 없이 403
- 생성/갱신: 크론 없이 요청 시 실시간 집계(로그 크기 임계 넘으면 캐시 5분)

## 4. 구현 순서 (검수 후)

① repo 발판·8025 기동(봇 카드+모델 표 = /status 확장) → ② usage-log.jsonl 수집 시작(회의방 패치)
→ ③ 토큰 트렌드 차트(프록시 로그 파서) → ④ 모델 변경 API+UI(이사님 토큰) → ⑤ 홈 사이트맵 추가
