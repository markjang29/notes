## 1. 흐름 (이사님 확정 순서)

01 수집 → 02 로드셋·리수 검증 → 03 matrix 자산화 → 04 그림·아케이드

- 01A/01B(소설·아카 채굴)는 **전체 파이프라인이 도는 것을 확인한 뒤** 시작한다.
- 02의 로드셋은 이사님도 직접 세팅할 수 있다. 02가 리수 검증을 통과하면 03이 matrix 자산으로 만든다.

## 2. 단계별 표 (담당 봇 = roster username)

### 01 수집
- 담당: heav_lnx_novel_col_bot(소설, awslnx), heav_firebat_zcode_bot(아카 자산, firewin)
- 입력: 원천 글·이미지 / 출력: 원본 byte + sha256 원장(asset_ledger.jsonl)
- 게이트: 자동(SHA-256 중복 0, provenance 6필드 완비)
- 실패 시: 원장에 오류 상태 기록 후 보류

### 02 로드셋·리수 검증
- 담당: heav_firebat_claude_bot(firewin) — 로드셋·장바구니. 리수 실행 환경은 PocketRisu 8013.
- 입력: 01 산출 자산 / 출력: 검증 통과한 로드셋(rs-l-… ID) + 3회 채팅 검증 로그
- 게이트: 자동(정합성 사전검사 G1~G4, 3회 채팅) → 검수(사람 승인)
- 실패 시: 장바구니 rejected + 사유 기록
- 미결: 02 환경에 Python이 없다(설치 vs node 이식은 이사님 결정). 5단계 3회 채팅 검증은 아직 미실행.

### 03 matrix 자산화
- 담당: heav_lnx_asset_agent_bot(awslnx) — 리수 분해, 원장, 후보 제출
- 입력: 승인된 로드셋 / 출력: release ID + provenance
- 게이트: 인가(이사님 승인)
- 실패 시: 승인보드 반려, 02로 환원
- 미결: S3(승인 레코드 → release 자동화)는 구축 전. 담당 배정 근거가 문서마다 다르다(zcode vs asset_agent).

### 04 그림·아케이드
- 담당: heav_gmwin_zcode_bot(그림), heav_lnx_arcade_bot(아케이드)
- 입력: release ID, 장면 / 출력: 이미지 매니페스트, 플레이 가능 자산
- 게이트: 검수(교차 감사, UI 게이트)
- 미결: 그림 생성은 8016 대신 nai-queue 8026이 실측 경로(picture-flow-messages-v1은 계획 단계)

## 3. 단계 사이 인계 (현재 없음 — 미구현)

- 01→02, 02→03, 03→04 모두 자동 인계가 없다. 사람이나 매니저가 8024로 손으로 보낸다.
- 인계는 `handoff-contract-01-04.md`의 4필드(근거·미완료·블로커·다음)를 담은 8024 task 메시지로 한다. ref에 단계 코드(예: 01→02)를 넣는다.

## 4. 번호 체계 정리 (실측)

- roster `seq` 중복 3쌍: 00(aws512, lnx), 01(novel_col, firebat_zcode), 04(gmwin_zcode, arcade).
- role 라벨의 사이트 표기가 실제 site와 다르다 (예: 01 novel_col "GM윈도" → 실제 awslnx).
- 조치안: `seq`는 유지하되 `lane` 필드(예: 01A, 01B)로 분리한다. 04는 04G(그림), 04A(아케이드). roster 갱신은 이사님 확인 후.
