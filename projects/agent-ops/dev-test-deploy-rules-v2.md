# 봇 표준 사이클 v2 — 탐색·구현·리뷰·자동화 (이사님 09-20 확정)

> Claude Agent SDK 코어 원칙 준용. 전 봇 공통 적용.
> v1(dev-test-deploy-rules-v1.md)을 대체.

## 0. 대원칙

- 실행 전에 계획이 먼저 나온다 (Plan 모드)
- 구현보다 테스트가 먼저 작성된다 (TDD)
- 실패를 직접 보고 스스로 고친다
- 되돌릴 수 있고 검증할 수 있으면 자동, 둘 다 아니면 사람이 실행

## 1. 개발 사이클 (TDD 워크플로우)

### 1-1. 명세 먼저 (Plan)
- 요구사항 달성에 따른 테스트를 먼저 명세한다
- 무엇을 만들지, 어떻게 검증할지를 문서로 확정 후 시작

### 1-2. 실패 관찰 (Red)
- 테스트만 먼저 작성하고 전부 실패 확인 후 멈춘다
- 이사님이 진행하라고 하면 그때 구현 시작 (Red → 승인 → 구현)

### 1-3. 구현 (Green)
- 실패 출력을 읽고 스스로 고친다
- 전체 테스트 통과까지 반복한다
- 완료 기준: 숨은 단위테스트 n개 전부 통과 + 실패시 원인 로그 필수

### 1-4. 환경 3층
| 층 | 용도 | 접근 |
|---|---|---|
| dev | 개발·테스트 실행 — 깨져도 무방 | 해당 봇 |
| staging | 테스터 검증 + 이사님 미리보기 | 테스터 + 이사님 |
| prod | 운영 — 승인된 것만 | 전원 |

## 2. 자동화 판단 기준

- **자동**: 되돌릴 수 있고(git tag/rewind) 검증할 수 있으면(테스트 존재)
- **수동**: 둘 중 하나라도 없으면 사람(이사님)이 실행 결정

## 3. 문제 해결 (서브에이전트 활용)

- 필요한 만큼 병렬 서브에이전트를 띄워 후보를 조사
- 후보가 여러 개면:
  1. 유력한 것부터 수정안 2~3개 작성
  2. 서로 비교평가
  3. 최선안만 적용
- 수정할 때마다 테스트 수행 → 실제 개선 여부 확인 → 개선될 때까지 반복
- 더 이상 유의미한 개선 없다고 판단되면 멈추고:
  - 시도한 것 · 적용한 것 · 남은 리스크를 정리해서 보고

## 4. 롤백

- Claude 기준: /rewind (체크포인트 복원)
- Git 기준: 이전 tag로 재배포
- 봇 서비스 기준: 릴리즈 디렉터리 스냅샷 이전본으로 symlink 전환

## 5. 지식 관리 계층

### CLAUDE.md / AGENTS.md 정책 계층화
```
최상위: 대원칙 (이사님 지시, 절대 금지)
  ↓
중간:   프로젝트 규칙 (스택, 경계)
  ↓
하위:   모듈 세부 (함수 단위 주석)
```
중요한 것일수록 위에서부터.

### 저장 위치
- **지식** (개념, 결정, 아키텍처): .md 파일에
- **절차** (반복 작업, 실행 순서): skill에 정의
- **대답**: 불필요 노이즈 금지 — 물어본 것에만 답한다

### 플러그인
- skill + command + agent + MCP + hook 설정을 1개로 묶은 것
- 프로젝트별로 plugin 폴더에 통합

### 외부 연결 (MCP)
- GitHub, 문서시스템, 외부 API 연결은 전부 MCP 경유
- REST API 서버와 동일한 개념 — 봇이 외부 시스템을 호출하는 표준 창구

## 6. 보고 규칙

- "완료" = 숨은 테스트 전부 통과 + 테스터 검증 완료
- "반영 완료" = prod에서 실측 확인
- 그 전에는 "staging 반영" 또는 "테스트 실패 확인(구현 대기)"
- 실패 시 원인 로그 첨부 필수

## 7. 위반 시

- 테스트 없이 구현: 즉시 중단 + 테스트부터 작성
- staging 미거쳐 prod 직행: 롤백 + 경고
- "완료" 오남용: 보고 무효 — 재검증 후 재보고
