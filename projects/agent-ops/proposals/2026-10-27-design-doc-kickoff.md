# 설계문서 1판 프로젝트 — 킥오프 결정 기록

## 배경

이사님 10-06 지시: "markjang29 내의 모든 git을 순차 전수검사하여 설계 관련 부분을 문서화.
텔레그램 봇 제어가 주 업무환경이라 git 소스 리뷰가 어렵다 → 내가 이해 가능한 형태로 구현
요구사항을 재정비, 추후 그 문서를 수정하며 바이브 코딩한다. 익숙한 도구는 업노트(평생 무료).
노션·옵시디언은 장점이 명확하면 검토. 모바일 친화적이어야 한다."

매니저 제안(10-06~10-27 채팅, 이 문서가 notes 내 첫 기록):
- **7장 구조**: 00 한장요약 / 01 시스템지도 / 02 서비스대장 / 03 기능요구사항 /
  04 결정기록 / 05 봇조직도 / 06 운용규칙
- **5단계 계획**: ① 22개 저장소 한줄요약 → ② 서비스·역할 대장 → ③ 요구사항(이사님
  발언 원문 대응) → ④ 결정기록 소급 → ⑤ 유지보수 절차
- **도구 비교**: 업노트(익숙·평생무료) vs 노션 vs 옵시디언 → 권장은 **옵시디언+git 동기화**
  (마크다운 원문이라 notes와 같이 버전관리됨, 모바일 앱 있음). 최종은 이사님 결정.
- 조사 작업용 단일 HTML 페이지 설계(5탭) 제안.

## 이사님 결정 (2026-10-27, 매니저 리뷰 보고에 대한 회신)

1. **게임 개발 스킬 4종 검수안 확정(채택)** — RPG 봇 10-23 정독 검수 그대로:
   - 통짜 설치 반대, 선별 융합.
   - awesome-gamedev-agent-skills(Godot 세트·rpg·create-game-assets) 1순위 융합.
   - sprite-gen은 로컬 파이프라인만(이미지젠 API는 과금·자격증명으로 제외).
   - Game Studios는 GDD·ADR 등 문서 양식만 차용.
   - superpowers는 절차(증거검증·체계적 디버깅)만 게임개발 사칙으로 재작성.
   - 실행: RPG 봇이 자체 계획 2~4단(격리 POC → 사칙화 → 승인보드 후보) 진행.
     매니저가 10-27 확정 통보함.
2. **"택틱 구성도" = 업무플로우 도식화** — 프로세스 분리·통신·데이터 전달의 도식.
   → [workflow-comm-v1.md](../workflow-comm-v1.md)로 착수. 설계문서 01장·05장의 재료.
3. **open web ui 도입 = 문서 1판 완성 후 재검토** (순서 합의).

같은 리뷰에서 **보류·반려**된 메모 항목(근거와 함께):
- cline/kanban **보류** — CLI 에이전트 병렬 실행 칸반. 현 발령 체계(매니저→98)+Taiga+승인보드와
  기능 중복. 22개 저장소 조사를 병렬로 돌릴 단계에서 재검토 가치 있음.
- CUA(computer use agent) **현재 반려** — GUI 조작 AI. 위험(오조작 복구 불가·권한 노출) 대비
  편익 없음(이미 API/CLI 자동화). GUI 전용 작업이 생기면 격리 환경에서만 재검토.
