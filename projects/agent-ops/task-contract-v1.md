# Task Contract v1 — 작업 지시서 7필드

> 근거: homeserver-target-design-v1.md §3 (이사님 09-06 승인).
> 규칙: **이 7칸이 채워지지 않은 지시는 배정하지 않는다.** 매니저(분배자)가 칸을 채우고,
> 실행 봇은 칸 밖으로 나가지 않는다. ELI5: "뭘 시킬지·어디까지 만지고·무엇으로 검수할지" 적힌 작업 지시서.

## 7필드

1. **repo** — 어느 저장소인가 (위치 포함: AWS/홈 리눅스/GM 윈도우).
2. **인수조건(완료의 정의)** — 무엇이 참이면 끝인가. 측정 가능하게.
3. **허용 모듈/경로** — 만질 수 있는 파일·디렉터리 화이트리스트.
4. **원천(source-of-truth)** — 정답이 어디 있는가(notes·schema·기존 구현). 추측 금지.
5. **예상 테스트** — 통과해야 할 검증(빌드·테스트·curl 실측 등).
6. **금지 변경** — 건드리면 안 되는 것(스키마·타 봇 영역·시크릿 등).
7. **산출 형식** — 결과의 모양(커밋+회의방 보고 / 문서 경로 / 카드 갱신).

## 운용 규칙

- 병행 작업은 git worktree 격리(설계 §3). 게이트: 빌드·테스트·아키텍처(Modulith verify)·
  provenance·보안·UI — 통과 증적만 이사님 보고(2단 승인).
- 산출 보고는 회의방(8023) 단일 채널. 매니저가 취합해 이사님께 ELI5 보고.
- 기존 Agent Mail v2·RELAY 티켓과 병행 — 기존 티켓에 7칸 라벨로 점진 적용(일괄 개정 아님).
