# 감사 의견 — 승인 다ossier 제안 v0

근거: `APPROVAL-DOSSIER-PROPOSAL.md` @ `c09c9928b496d9484faf08b181befa8f474db780` 및 후속 회의록. 아래 평가는 실존 `source-unit`에서 출발한 자산만 대상으로 하며, 봇이 만든 예시는 승인 대상 근거로 승격하지 않는다.

## 낙관 근거

- 승인 카드를 다ossier의 마지막 장으로 내리면, 이름·설명만 그럴듯한 카드가 검증 전에 승인되는 현재의 순서 오류를 바로잡을 수 있다.
- **리수 셋업**의 실제 조합 JSON, **3회 채팅** 전문, **NAI** 시도 결과, **GATE** 검사 목록, **활용도** 점수 근거, **액션** 원문 링크를 한 묶음으로 고정하면 이사님이 요약 대신 재현 가능한 증거를 확인할 수 있다.
- 단계별 마블 수와 정체 구간을 보이면 누락·비용·실패를 승인 화면 뒤에 숨기기 어려워진다. 특히 실패 결과도 보존하면 성공 사례만 골라 제시하는 편향을 줄일 수 있다.

## 비관 근거

- 링크가 있다는 사실은 진본성을 보장하지 않는다. 다른 `source-unit`의 셋업·채팅·이미지·GATE 결과를 재사용하거나, 승인 직전 JSON을 바꾸고 썸네일만 유지하면 7요소가 모두 채워진 것처럼 위조할 수 있다.
- **리수 셋업**은 source-unit ID·원문 해시와 카드/모듈/로어/모델 버전이 결합되지 않으면 바꿔치기 가능하다. **3회 채팅**은 좋은 3회만 재실행·선별하거나 전문을 잘라낼 수 있다. **NAI**는 프롬프트와 결과의 대응, 실패·재시도 횟수, 생성 설정이 빠지면 타 결과를 붙일 수 있다.
- **GATE**는 검사기 버전·규칙 묶음·입력 해시·전체 결과가 없으면 구버전 실행, 일부 검사 생략, fail을 pass로 전사하는 우회가 가능하다. GATE 통과 뒤 입력을 수정하는 TOCTOU도 막지 못한다.
- **활용도**는 태그를 자가 부여해 점수를 부풀리거나 봇 창작 시나리오를 실존 자산의 가치로 오인시킬 수 있다. **액션 링크**가 가변 최신본을 열면 심사본과 체험본이 달라진다. **승인**을 다ossier 완성 전 생성·예약하거나, 승인 후 구성요소를 교체해도 release가 유지되면 순서 규칙은 UI 장식에 그친다.

## 수정안

1. 다ossier마다 불변 manifest를 만들고 `source-unit` ID·원문 해시, ① 셋업 JSON과 모든 구성 버전, ② 3회 전 전문·실행 ID·시각·선정 규칙, ③ NAI 프롬프트/설정/결과 해시와 모든 시도, ④ GATE 검사기 commit·규칙 버전·입력 해시·전체 pass/fail, ⑤ 활용도 산식·태그 출처·후보 세계와 점수, ⑥ 심사본 고정 액션 링크를 묶어 digest를 계산한다.
2. 각 단계는 전 단계 digest를 참조하는 append-only 이벤트로 기록한다. 실패·재시도·제외 사유도 남기고, 서로 다른 자산 간 증거 재사용을 거부한다. 자동 GATE는 동일 manifest를 다시 읽어 source-unit 계보, 스키마, 재현성, 누락, 검사기 버전을 검증한다.
3. 활용도에서 봇 창작은 명시적으로 `example_only`로 격리하고 점수 입력에서 제외한다. 태그는 source-unit 파싱 결과 또는 검토된 사전 근거만 허용하며 근거 없는 수동 태그는 GATE fail로 처리한다.
4. 순서를 상태기로 강제한다: `source-unit 고정 → 리수 셋업 → 채팅 3회 → GATE → NAI → 활용도 → 다ossier seal → 이사님 열람·체험 → 승인`. 7요소 중 하나라도 미완성·불일치면 승인 버튼을 생성하지 않는다. 승인은 sealed digest에 서명하며, 이후 한 바이트라도 바뀌면 승인을 자동 무효화하고 재심사한다. release는 유효한 최종 승인 이벤트와 동일 digest일 때만 허용한다.
