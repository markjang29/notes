## 0. 기본 원칙 (이사님 지시)

- **Closed loop이 중요** — 모든 개발은 "지시→기획→구현→검증→보고"의 고리가 관찰 가능해야 한다. 이사님 발언=제12조 흐름(요구사항→검증→구현→완료보고) 준수.
- **안티 패턴 명시** — 반복되는 실수는 본 문서 §5에 목록화하고, 각 단계 게이트에서 재발 방지.

## 1. MVP 프로젝트 기획·문서생성 단계

| 산출물 | 내용 |
|---|---|
| PRD | 제품 요구사항 정의서 |
| 사용자 시나리오 기반 문서 | 페르소나·시나리오·수용기준 |
| 와이어프레임 | 화면 흐름·레이아웃 |
| ERD 및 데이터 모델 설계 | 테이블·관계·제약 |

## 2. Swagger 계약 우선 (Swagger-First)

1. 데이터 모델 기반으로 **Swagger(OpenAPI) 스펙 생성**
2. Swagger 기반으로 **백엔드 목업(Mock) 작성** — 프론트는 목업과 병렬 개발

## 3. MVP 백엔드 구현

- 데이터 모델 기반 DB 생성 (**MCP 연동** — §13조 CLI/MCP화와 연결)
- 백엔드 프로젝트 생성 · skill/사용자 정의 슬래시 명령어로 자동화
- 단위 테스트 · 보안 이슈 점검 · 개선사항 도출
- 문서화 작업

## 4. MVP 프론트엔드 구현

- 와이어프레임(HTML/JSX) → 프로젝트(React+Vite) 생성·프로젝트 룰·환경설정
- 디렉토리 구조·컴포넌트 분할·**컴포넌트 명세서** 작성
- 프롬프트 중심 개발 — **SOLID + Clean Architecture 준수**
- 단위 테스트·보안 점검·개선사항 정리·문서화
- 기능 연동 테스트·디버깅 → **E2E 테스트**

## 5. 배포 (CI/CD 게이트)

- **Supabase ↔ Vercel 연동** (백엔 인프라)
- **Vercel for GitHub** + **GitHub Actions CI/CD 자동화**
- 게이트: CI 통과(PR 확인·단위+E2E·보안 점검) 없이는 병합·배포 금지

## 6. 안티 패턴 (게이트에서 차단할 것)

1. 스펙 없이 코딩 시작 (PRD·ERD·Swagger 선생성 원칙 위반)
2. 문서·코드·DB·API 4개간 불일치 — 정본(Swagger·ERD)이 단일 진실
3. 테스트 없이 병합/배포 (CI 게이트 우회)
4. 리뷰·보고 없는 silent 구현 (ORG-RULES `silent_project_implementation` 금지와 일치)
5. 자격·완료 발명 (`invent_completion` 금지)

- 전 봇 숙지: 허브 @all 공지 + read-registry confirmations 등록(감사 evidence 규정 준수).
