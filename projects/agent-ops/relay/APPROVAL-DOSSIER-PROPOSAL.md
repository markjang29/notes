# 승인 다ossier 제안 v0 (전 봇 회의 안건 — 이사님 08-25 지시)

> 문제의식 (이사님 원문 요지): "시퀀스가 승인부터 하는 게 맞니? … 매트릭스 예상 활용도·기본 GATE 통과 검수도 가져오는 구조여야 하고, 마블이 파이프라인 따라 흐르는 게 보이고 중간에 확인할 수 있어야지. 지금 자산들은 봇이 임의로 지어낸 스토리 아니냐"
> 회의 방식: 각 봇이 낙관론·비관론을 나눠 의견 제출 → zcode가 종합 → 이사님 보고용 전체 안 + 승인 카드 실체 확정본.

## 1. 승인 카드의 실체 (제안)

승인 카드는 **"검증 다ossier의 마지막 장"**이어야 한다. 카드 하나에 반드시 포함:

```text
[자산 승인 카드 = 다ossier]
① 리수 셋업: 어떤 카드+모듈+로어+모델 조합이었는지 (실제 조합 JSON 링크)
② 3회 채팅 실사: 전문 링크 + 품질 지표(응답 길이·태그 준수·에러 여부)
③ NAI 이미지: 생성 시도 결과 썸네일 + 프롬프트 JSON 링크
④ 기본 GATE 검수: 하드차단 통과·스키마·재현성 등 자동 검사 결과 (통과/실패 목록)
⑤ 매트릭스 예상 활용도: 이 자산이 어느 세계·조합에 쓰일지 자동 산출 (태그 기반 매칭 점수)
⑥ 액션 링크: RISU에서 이어서 채팅 · NAI 페이지에서 재생성 · JSON 원문 보기
⑦ 그제서야 [승인 / 보류 / 폐기]
```

## 2. 순서 수정 (마블 흐름)

```text
자산 선택 → 리수 셋업 → 3회 채팅 → 자동검사(GATE) → NAI 시도
→ 활용도 산출 → ★다ossier 완성 → 이사님 열람·체험 → 승인 → release
```
- 이사님은 다ossier가 완성된 카드만 받는다 (불완전 다ossier는 아예 대기열 진입 불가)
- 파이프라인 각 단계에서 마블(자산) 상태가 홈(8018)에 보임: 어디에 몇 개가 걸려있는지

## 3. 임의 스토리 문제 (비관 포인트로 명시)

- 현재 보드의 스토리 카드는 시나리오 봇이 자의 생성한 것 — 자산 파이프라인과 무관
- 원칙: **승인 카드의 재료는 반드시 source-unit(실존 자산 파싱)에서 온다** — 봇 창작은
  다ossier의 "활용도 시나리오 예시"로만 쓰이고 승격 대상이 될 수 없다
