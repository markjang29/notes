# PIPE#60 [N3] comm 사이드카 점검 — 거점 봇 공통 지시 (매니저, 2026-10-01)

배경: 사이드카가 봇을 깨우면 새 세션이 열리는데, 그 세션이 8024 토큰 파일 위치를 몰라 사서함을 못 읽고 blocked로 멈춘 사례가 있었다. 모든 거점이 같은 문제를 겪을 수 있어 현황을 확인한다.
정본: projects/agent-ops/comm/INSTALL-sidecar.md, principles/telegram-comm-protocol-v1.md

## 할 일 (수정 금지, 확인만)
1. 이 거점에 사이드카가 가동 중인지 확인한다 (프로세스 또는 서비스 상태).
2. 내 사서함의 읽지 않은 메시지를 whoami → inbox → ACK 순서로 처리한다. ACK 메모에 acknowledged 또는 blocked를 적는다.
3. 8024 comm 토큰이 어느 파일에 있는지 경로만 확인한다. 파일을 열어 내용을 읽거나 출력하지 않는다. TOKEN 항목이 있는지 여부만 확인한다.
4. 토큰이 없으면 만들거나 추측하지 않고 "토큰 경로 없음"으로 회신한다.
5. 사이드카가 없으면 설치하지 않는다. Python·NSSM 설치는 이사님 승인 후에만 한다. "미설치 — 설치 승인 요청"으로 회신한다.

## 금지
- 토큰 값을 채팅·메시지·커밋·로그에 쓰지 않는다.
- 다른 봇의 사서함을 읽거나 대신 ACK하지 않는다.
- 설정·서비스·cron·방화벽을 바꾸지 않는다.

## 회신
8024로 매니저(heav_lnx_bot)에게 type=task, ref=PIPE#60, 3줄로.
(a) 사이드카 가동 여부 (b) 미수신 건수와 처리 결과 (c) 토큰 경로와 TOKEN 항목 유무(값 없이)

## 거점별 참고
- firewin: 파뱃 zcode가 점검을 끝냈다. C:/sidecar/ 에 사이드카 가동 중(PID 9236). 같은 PC면 같은 사이드카일 수 있다.
- gmwin: 실측 정정 — 사이드카 가동 중이다(09-24부터. 10-01 04:23 zcode 회신: PID 6088, 미수신 0). "문서 미설치" 표기는 구식.
- gmlnx(개발팀장 zcode): comm-relay-gmlnx 서비스가 있다. 이 봇의 폴러(room-poller-gmlnx-zcode)가 8023만 보고 8024를 읽지 않는지, 8024 사서함을 스스로 확인하는 경로가 있는지 (a)에 함께 적는다.
- aws512: 문서에는 미설치. 실제 상태 확인 필요. (asus는 삭제된 봇이라 대상 제외)
