# [spec] 요구사항 정제
- jira: RELAY-42
- 작성일/기준일: 2026-08-23 KST
- 대상: `markjang29/music_video`, AWS 서비스 `http://13.125.131.126:8020`

## 사용자·상황 정의

- 대상 사용자는 **한국인·베트남인 커플**이다. `req.md` 배경의 “한국인·일본인 커플”은 원문과 충돌하는 오기이며 구현 근거로 사용하지 않는다.
- 외국인 배우자는 현재 한국의 어학당에 재학 중이고, 한국어 의사소통 입증 수단으로 TOPIK 응시를 준비한다.
- 사용자가 원하는 순서는 “한국 혼인신고 먼저”이다. 다만 실제 접수 가능 서류와 후속 베트남 등록 효과는 관할 가족관계등록관서·베트남 관할기관의 최신 안내에 따라 달라질 수 있으므로, 페이지는 가능 여부를 확정하지 않고 **사전 확인 게이트**와 공식 문의처를 제공한다.

## 모호 용어 정의

- “아스티포유”는 웹 조사 결과 별도 서비스명이 아니라 **아포스티유(Apostille)**의 발음·표기 혼동으로 해석한다.
- 베트남의 1961 아포스티유 협약 발효일은 **2026-09-11**이다. 협약은 베트남과 가입을 수락한 당사국 사이에서 적용되며, 대상 문서·발급기관·번역 필요 여부·접수기관의 추가 요구까지 자동 면제한다는 뜻은 아니다.
- “일상”은 기존 후쿠오카 여행/MV 기능과 분리된 개인 생활 관리 영역이다.
- “여행”은 현재 서비스의 후쿠오카 일정, 촬영 목록, MV 러프컷, 영감 보드, 여행 링크와 편집 API를 그대로 포함하는 영역이다.

## 측정 가능한 완료 조건

### 1. 정보 구조와 기존 기능 보존

- 첫 진입 화면에서 `여행`과 `일상` 두 영역을 명확히 선택할 수 있다.
- `여행` 진입 시 기존 후쿠오카 기능(날짜 선택, 촬영 체크, 촬영 편집 5필드, KO/EN/VI 전환, MV 러프컷, 영감 보드, 여행 링크)이 손실 없이 동작한다.
- `일상` 진입 시 `혼인 · TOPIK · F-6` 페이지가 열리고, 브라우저 뒤로가기/영역 전환으로 여행에 복귀할 수 있다.
- 390px 모바일과 1440px 데스크톱에서 가로 오버플로가 없고 주요 버튼·입력·대화상자가 화면 밖으로 벗어나지 않는다.

### 2. 일상 페이지 기능

- 첨부 HTML의 일정 CRUD, 서류 CRUD, 상태, 비용 집계, 발급일 기준 관리 알림, JSON 백업을 참고해 구현한다.
- 일정과 서류 데이터는 기본적으로 브라우저 `localStorage`에 저장하며 서버/Git에 개인 입력값을 자동 업로드하지 않는다.
- 일정 항목은 최소 `날짜, 단계, 제목, 상태, 예상비용, 메모`를 가진다.
- 서류 항목은 최소 `문서명, 담당자, 국가, 사용처, 상태, 발급일, 관리용 최신본 기준, 번역, 공증, 인증, 메모`를 가진다.
- 사용자는 항목 추가·수정·삭제, 상태 변경, JSON 내보내기를 수행할 수 있다.
- 기본 데이터와 화면 문구는 한국어·영어·베트남어로 제공된다. 사용자가 직접 입력한 문장은 자동 번역하지 않아도 되며 원문을 보존한다.

### 3. 절차 표현과 공식 출처

- 페이지는 다음을 서로 다른 단계로 구분한다: `한국 혼인신고 사전확인/접수`, `베트남 측 후속 등록·문서`, `TOPIK/의사소통 입증`, `F-6 준비·신청`, `체류자격 변경 또는 출국 후 사증 신청 여부 확인`.
- “한국 혼인신고 먼저”는 사용자 계획으로 표시하되, 외국인 배우자의 혼인성립요건 구비증명 등 실제 서류는 관할 시·구·읍·면 가족관계등록 담당자에게 접수 전에 확인하도록 경고한다.
- D-4 재학 상태에서 F-6로 변경할 수 있다고 단정하지 않는다. 현재 체류자격, 국내 변경 허용 여부, 관할 출입국의 추가 서류를 Hi Korea/1345에 확인하도록 표시한다.
- TOPIK은 F-6 의사소통 입증의 유일한 방법이라고 표현하지 않는다. 일반 안내에서는 TOPIK 1급 이상을 한 입증 수단으로 설명하고, 교육기관 이수·국내 계속 체류 등 다른 인정 가능 자료와 면제 여부가 있음을 함께 표시한다.
- TOPIK 회차별 접수·시험·발표일은 TOPIK 공식 공지와 일치하는 값만 기본 일정에 넣는다. 확인되지 않은 제109회 `9/1~9/7`, `11/15`, `12/22` 값은 그대로 배포하지 않는다.
- F-6 소득·주거·의사소통·관계입증 등은 신청처와 신청 시점에 따라 변동될 수 있음을 표시한다. 숫자를 넣을 경우 연도와 공식 출처를 함께 표시한다.
- 모든 법무·시험 정보 카드에 `기준일`과 클릭 가능한 공식 출처 링크를 표시한다.

### 4. 2026-09-11 베트남 아포스티유 반영

- 2026-09-11 이전과 이후를 구분하는 안내를 제공한다.
- 발효 전에는 베트남이 아포스티유 협약 비회원국이라는 과거 안내를 현재 절차처럼 고정하지 않는다.
- 발효 후에는 적격 공문서가 단일 아포스티유 인증으로 간소화될 수 있음을 설명하되, 한국-베트남 간 적용관계, 문서 범위, 번역, 원본/등본, 제출기관 추가 요구를 별도 확인하도록 한다.
- 베트남 측 발급 권한기관 안내에는 최소 `베트남 외교부 영사국(하노이)`과 `호찌민시 대외관계 담당기관`을 공식 출처와 함께 표시한다.

### 5. 개인정보·보안

- 여권번호, 주민등록번호, 외국인등록번호, 인증 토큰, 실제 문서 스캔본을 Git 기본 데이터에 넣지 않는다.
- 사용자 입력을 DOM에 표시할 때 `textContent` 또는 동등한 안전한 API를 사용하며 입력값을 `innerHTML` 문자열로 삽입하지 않는다.
- JSON 가져오기를 추가한다면 스키마·크기 검증과 사용자 확인을 거치며 임의 HTML/스크립트를 실행하지 않는다.
- `.git`, 환경 파일과 숨김 경로는 현재 서버에서 계속 404여야 한다.

### 6. 테스트와 릴리즈

- `node --check app.js`, `python3 -m py_compile server.py`, `git diff --check`가 통과한다.
- 자동 또는 수동 브라우저 테스트로 390px/1440px에서 여행↔일상 전환, KO/EN/VI, 일정·서류 CRUD, 새로고침 후 저장 유지, JSON 백업, 기존 여행 기능을 검증한다.
- `/`, `/api/content`, `/api/health`가 정상 응답하고 기존 촬영 편집·GLM 번역·Git 저장 API 회귀가 없어야 한다.
- 배포는 `main`의 RELAY-42 커밋을 AWS 작업 디렉터리에 fast-forward한 뒤 systemd 재시작 또는 정적 변경 반영 확인으로 수행한다.
