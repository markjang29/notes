# [req-첨부] 소프트웨어 요구사항 초안 — 게임 자산 워크벤치
- jira: RELAY-36
- 성격: 이사님 지시("소프트웨어 적인 요구사항이 있어야지", 2026-08-22)로 작성한 **요구 단계 첨부 초안**.
  측정 가능 조건 확정·우선순위 확정은 2-정제(aws-manager) 소관.
- 범위: NAI(NovelAI Opus) 기반 게임 자산 제작 웹 도구. 알만툴(RPG Maker)처럼 브라우저에서
  우리 자산을 게임에 투입되는 이미지 단위로 만들고·분류하고·리롤하는 프로그램.

## 기능 요구 (FR)

### A. 생성 코어
- **FR-1 자산 유형 프리셋** — 캐릭터 / 무기·장비 / 월드(배경·지형·오브젝트) / 아이템·오브 / UI 요소
  유형별 프롬프트 템플릿을 갖는다. 템플릿은 변수(분위기·팔레트·스타일·포즈·구도)로 조합된다.
- **FR-2 생성 실행** — 모델(nai-diffusion-3 / v4.5-full) 선택, 사이즈 프리셋(오피스 무료 조건 기본:
  832x1216, 1024x1024 등 ≤1MP), 스텝(≤28 기본), 시드(지정/랜덤)로 생성한다.
- **FR-3 리롤** — ①같은 프롬프트+시드만 변경 연속 리롤 ②시드 고정 재생성(결정적 검증) ③프롬프트 일부만
  수정한 변형 생성. 리롤은 원본을 보존하고 새 결과를 형제 항목으로 추가한다.
- **FR-4 배치 스크립트** — JSON 배치 정의(프롬프트 배열)로 N종 일괄 생성. RELAY-34 batch1/batch2.json
  형식과 호환된다.
- **FR-5 후보 비교** — 갤러리에서 후보 2~N장을 나란히 비교하고, 프롬프트·파라미터 diff를 표시한다.

### B. 자산 관리
- **FR-6 자산 ID·분류** — 생성물에 고유번호 체계(CHR/MOD/PRM/META/SCN/DRF-NNNN) 기반 ID를 발급하고,
  유형·태그·소속 월드·상태(초안→후보→승인→폐기)로 분류·검색·필터한다.
- **FR-7 계보 추적** — 리롤/변형의 부모-자식 관계(시드 계보)와 파생 이력을 기록한다.
- **FR-8 메타데이터 정본** — 모든 이미지에 1:1 대응 JSON 메타(prompt, negative, model, seed, steps,
  scale, size, 생성시각, 자산ID, 상태, 계보)를 저장한다. Git에는 PNG 없이 메타만.
- **FR-9 스타일 프리셋** — 도트(파랜드식)/핸드페인팅/일러스트 등 렌더 스타일을 템플릿 변수로 제공한다.
  **도트 채택 미결정에도 도구가 동작**해야 한다(스타일 추가만으로 전환 가능).

### C. 매트릭스 연계·보관
- **FR-10 매트릭스 자산 주입** — 매트릭스 자산(고유번호 보유)을 참조해 그 프로필(외형 키워드 등)을
  프롬프트에 주입해 캐릭터화한다. 매니페스트는 RELAY-35 표준과 호환.
- **FR-11 내보내기·보관** — 승인 자산을 구글드라이브 `matrix-upload:RPG저장고/` 로 업로드(rclone 연계),
  로컬 export(PNG+메타 JSON 묶음)를 지원한다.

## 비기능 요구 (NFR)
- **NFR-1 접근** — 브라우저 웹 UI. 데스크톱 우선, 이사님 폰(모바일)에서 결과 확인 가능한 반응형.
- **NFR-2 보안** — NAI 토큰은 서버 사이드 시크릿(파일/환경변수)로만 보관, Git·프론트 노출 금지.
  웹 접속은 간단 인증(이사님 전용).
- **NFR-3 비용 보호** — Anlas 소모 가능한 조건(>1MP, >28스텝, 복수장)은 기본 잠금 + 명시 해제 시만 허용.
- **NFR-4 스택** — Python(FastAPI) + 정적 프론트(경량). 기존 `matrix_asset_agent/tools/workbench_web.py`
  스택과의 정합 검토 후 확장/신규 결정(4-설계). NAI API는 어댑터 레이어로 격리(모델 버전업 교체 대응).
- **NFR-5 성능** — 1장 생성 수십 초 이내(NAI 응답 의존), 갤러리는 페이지네이션/지연로딩.
- **NFR-6 내구성** — 생성 기록은 서버 재시작 후에도 유지(파일 기반, DB 불필요 수준).
- **NFR-7 운영** — 서버(우분투)에서 1커맨드 기동, 포트는 기존 관리 체계(port-registry)와 조율.

## 수용 기준 예시(초안)
- 브라우저에서: 유형 선택 → 프롬프트 편집 → 생성 → 리롤 3회 → 후보 비교 → 승인 표시 →
  자산 ID 발급 → 드라이브 업로드까지 **중단 없이 한 흐름**으로 완결된다.
- 동일 시드+파라미터 재생성 시 동일 이미지(결정성)가 확인된다.
- 배치 JSON 10종 일괄 생성이 수행되고 전부 메타 JSON과 1:1 대응된다.
- 생성된 어떤 이미지도 프롬프트·시드·모델을 조회할 수 없는 경우가 없다.

### 벤치마크 — RPG메이커 MZ가 증명한 구조
- 자산을 그림 단위가 아닌 **게임 내 역할별 폴더**로 관리: characters / sv_actors / enemies /
  tilesets / battlebacks1·2(전장 2층: 원경+지면) / parallaxes / animations / system(UI).
- **이미지 폴더와 데이터베이스(게임 데이터)가 분리+상호참조**: actors→classes, skills→animations,
  troops→enemies+battlebacks. Notes 필드로 메타 부기.
- **도구가 규격을 강제**: 타일 48x48, 캐릭터 시트 3x4 프레임, $ 접두 컨벤션 — "뽑는 것"이 곧 "투입 가능"해지는 지점.
- AI 도구 동향: Scenario(스타일 DNA 학습 일관 생성 — 우리 "세계별 문법"과 동일 사상), Meshy(2D→3D).

### 우리 구도 — 3레이어 상황판 (Asset Command Board)
1. **설정층 (주문서)** — 매트릭스/시나리오의 세계(SCN)·캐릭터(CHR) 자산 카드. 고유번호·세계관 프로필·
   전투 문법. 디자인 팀이 여기서 요청을 받는다.
2. **제작층 (뽑고·고치고·업그레이드)** — NAI 워크벤치(현재 프로토타입). 유형=게임 역할:
   WLD(전장·월드) / CHR(캐릭터: 도트+일러스트) / **EFX(이펙트 — RPG 컨셉[패링 히트스톱·눈 인터페이스·
   공격 분류 텔레그래프]에서 파생)** / WPN / ITM / UI. 리롤 계보·버전 관리·승인 파이프라인(초안→후보→승인).
3. **투입층 (매핑)** — 승인 자산을 게임 역할 슬롯에 연결(이 전장=WLD-003, 이 캐릭터 도트=CHR-012).
   내보내기 규격: RPG메이커 표준(타일 48px·시트 3x4) + 우리 엔진(Godot) 규격 병행.
