## 개념 정리

- 단말 10대 = 매트릭스의 **출력 전용 렌즈(렌즈/디스플레이)**. 단말은 "보여주기만" 하고,
  무엇을 비출지는 매트릭스 서버가 정한다(원격 지정).
- 표시 대상: 캐릭터 카드, 자산(R/N 번호) 상세, 파이프라인 흐름 보드, 승인 대기, 보고함,
  아케이드 등 기존 웹 뷰 전부.

## 3단계 접근 (매니저 제안)

1. **0단계(즉시, 개발 거의 0)** — 각 단말 크롬에서 기존 사이트 URL을 열고 "홈 화면에 추가"
   (PWA 풀스크린). 단말마다 URL 하나 지정으로 끝. 단말 번호 스티커(D1~D10).
2. **1단계(소규모 개발)** — 단말 등록 페이지: 단말가 스스로 등록하면 서버가 단말→뷰 매핑을
   원격 지정·변경(단말 재세팅 불필요). 풀스크린 전용 렌즈 뷰(auto-refresh). P/C·R/N 번호 체계와
   연결("D7 렌즈 = R012 카드").
3. **2단계(이후)** — VR: 웹 기반이므로 WebXR 경로로 자연 확장. 단말이 그대로 VR 뷰어 소스가 됨.

## 미결정 (이사님 결정 필요)

- 1차 용도 배정: 10대에 뭘 보여줄지(예: 파이프라인 보드 1 · 승인 대기 1 · 캐릭터 카드 N ·
  보고함 1 …).
- 단말 세팅 주체/시기(이사님 물리 세팅 필요 — 서버는 설정값만 제공).
- 우선순위: 현행 RELAY-54 정합성 복구·RELAY-57 번호체계와의 순서.

## 왜 가치 있는가 (매니저 소견)

- "마블이 파이프라인을 흐르는 게 보이는 구조"(이사님 RELAY-52 요구)의 물리적 구현체 —
  벽에 걸린 화면 = 살아있는 대시보드.
- 승인 대기·캐릭터 상태가 상시 노출되어 이사님 결정 사이클 단축.
- 단말이 출력 전용이면 보안·권한 문제 최소(조작 불가, 보기만).
