## 2. 아키텍처 요구사항 — 팔란티어형 자산 파이프라인

### 2-1. 원사이트 통합 우선 원칙 (강제)

- 신규 기능을 요구받았는데, 원사이트(스프링부트+리액트)에 별도 페이지로 개발하는 게 아니라
  **따로 web을 띄우고 그 링크만 연결하는 구조라면 → 반드시 원사이트 통합을 먼저 제시할 것.**
- 단, 특수 목적 사이트는 논의 후 제외 가능.

### 2-2. 전체 흐름 가시화

- **팔란티어 베이스**: 파이프라이닝 · 객체화 · 대시보드화 · 오브젝트화.
- **matrix core → 시나리오 → RPG**로 이어지는 **전체 flow가 보여야 한다**.
- 같은 원천에 대해 여러 조합·변경으로 **다른 느낌의 자산**이 나오는 구조.

### 2-3. 파이프라인 (원천 → 앱서비스, 11단계)

1. **원천 데이터 수집** — 소설 · 아카 수집 (담당: 파뱃윈도 Aka 자산)
2. **소설 → NAI 이미지 생성**으로 장면 이미지 확보
   (생성 툴은 아카 자료 중 NAI 툴·플러그인을 해체해 지속 고도화 — 이를 위한 웹 별도 존재)
3. **아카 자료 → 바구니 담기·꺼내기** — 리수 검증을 위한 파이프라이닝
4. **로드셋 세팅**(아이템 착용 느낌) + **validation**
   — 페르소나가 여러 개면 안 됨, **Risu 정합성** 필수
5. **RISU 채팅 최소 3회 사용성 검증** (조합에 따라 결과가 달라짐)
6. **NAI 그림으로 느낌 더하기**
7. **자산 승인** — 승인 자산은 원천데이터의 특정 부분 가공 조건일 수 있음(팔란티어 참고)
8. **매트릭스 코어**
9. **매트릭스 엔진** → 디맨전 · 렌즈 적용
10. **RPG 또는 Matrix 인스타** 등 앱 서비스
11. 안정화 후 **각 수집 환경 · NAI 이미지 CLI화**

## 3. 개발 요구사항

- **통합 대상 repo: `markjang29/matrix-home`** — 여기로 통합한다.
- **모바일 프렌들리** 개발.
- **스프링 프레임워크 + React + REST API + DB** 베이스 구조.
- **독립 구현된 사이트는 제거 대상** — 원사이트 통합 홈 하위에 개발 후
  **commit → merge → push** 한다.
- 가능하면 **마이크로서비스 구조**.
- 웹은 **Vercel react-best-practices 스킬** 기반으로 모바일 최적화·리팩토링 검토.
  각 사이트(윈도우/리눅스 PC)별 **claude 위주로 먼저 스킬 추가**.
- **이사님 발언 = JIRA 요구사항** → 검증 → 구현 흐름.
- 개발 표준 상세: `conversation-rules-v1.md` §11~13, `ORG-RULES.md` §8.
