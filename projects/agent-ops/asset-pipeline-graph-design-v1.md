# 자산 파이프라인 그래프 설계 v1

> 이사님 09-08: "사이트 전부가 아니라 자산의 연결·파이프라인이 보이는 구조. 담당 봇이 다른데
> 업무 분배·게이팅 어떻게 할지 보고." 기존 정본 흡수: RELAY-49 7단계 · firewin 저장흐름 설계 v1 ·
> provenance 6필드 · 백업정책 v2.

## 1. 그래프 정의 (React Flow)

- **노드 = 파이프라인 단계**(각 노드 표시: 단계명 · 담당 봇 배지 · 게이트 아이콘 · 현재 자산 수).
- **엣지 = 자산 이동**(엣지에 게이트 종류 표기: 자동/인가/검수).
- **자산 = 흐르는 물건**: 상태값(수집→검증→원장→동기화→가공→게재→수익화 + 오류·보류)으로 원장에 기록.
- 뷰 2종: ①**라이브 뷰**(읽기 전용 — 자산이 어느 단계에 몇 장인지, 원장·큐 데이터 실시간)
  ②**편집 뷰**(단계 정의·담당·게이트 규칙 변경 — 이사님·매니저 전용).

## 2. 파이프라인 단계와 담당 (초안)

- 1 수집 — firewin(아카라이브·소설 큐 inbox/)
- 2 검증·중복제거 — firewin(SHA-256, provenance 6필드 완비)
- 3 원장 등록 — firewin(asset_ledger.jsonl 마스터번호, dedup_index)
- 4 저장·동기화 — firewin→gmlnx 미러→Google Drive 콜드(삭제금지·압축우선)
- 5 가공·파생 — 시나리오 팀·asset_agent(derived/ 분리, 원본 불변)
- 6 이미지화 — 이미지 스튜디오(8016 계승, ComfyUI 후보 검토 대상)
- 7 게재 — firewin(웹 오너십)·firebat(스프링 구현)·zcode(설계) → 원사이트 /assets·/cards·/dossiers
- 8 수익화 — rpg 팀·시나리오(게임·소설 제품)

## 3. 게이팅 — 전이 규칙

- **자동 게이트**(기계 검사, 통과 못 하면 자동 반려): 수집→검증(파일 무결성) · 검증→원장(SHA-256
  중복 0 + provenance 6필드 완비) · 원장→동기화(해시 일치·압축 완료).
- **인가 게이트**(사람 승인 — /approve 원사이트 화면에서): 동기화→가공(파생 생성 허가 — 원본 불변
  원칙 보호) · 게재→수익화(수익화 승인).
- **검수 게이트**(다른 눈 표본 검수): 가공→게재 — 감사(codex×claude 교차) + UI 게이트(모바일·
  카테고리 기준).
- 전이 기록: hub task 이벤트로 남김(멱등키 = 자산ID+단계) → 그래프가 실시간 뷰가 된다.

## 4. 업무 분배 원칙

- **단계 = 봇 = 책임**: 각 단계 노드의 owner 봇이 그 단계 전체를 책임진다(티켓 낱장이 아니라
  단계 소유제).
- **그래프 편집·deploy**: 이사님·매니저만(2단 승인 — save는 초안, deploy는 게이트 통과 후 적용).
- **매니저**: 파이프라인 전체 감독 — 단계 정의 변경 티켓화, 담당 분쟁 조정, n/20 진행률 보고.
- 데이터 원천: asset_ledger.jsonl · novel_queue.json · provenance 필드 · hub 이벤트 로그 —
  새 원장 만들지 않고 기존 원장을 그래프에 연결한다.
