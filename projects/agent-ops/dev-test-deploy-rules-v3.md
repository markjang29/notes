## 6. 코드 티켓 인수조건 필수화 (v3 신설)

### 6-1. 적용 범위
- 태그 `kind:코드` 티켓만. 운영·설정 티켓은 현행 게이트 유지.

### 6-2. 인수조건 표준 (Gherkin)
- 설계 단계 문서에 **Gherkin(Given/When/Then) 인수조건 ≥1개** 필수.
- 형식:
  ```
  Given <사전 상태>
  When <행동·입력>
  Then <관찰 가능한 결과 — 명령 1줄로 검증 가능해야 함>
  ```
- `Then`은 검증 명령과 1:1 대응(쉘 1줄 실행 결과로 판정 가능)이어야 한다.

### 6-3. 게이트 연동
- 인수조건 없는 `kind:코드` 설계 → **설계승인 불가** (디스패처 발령문 고지분, dispatcher.py build_msg).
- 테스트 동반 커밋 의무는 v2 §1(TDD) 그대로 — 무테스트 구현은 감사 반려.

### 6-4. 감사 반려 조항
- 감사봇(heav_lnx_audit_bot)은 코드 티켓 완료보고 검수 시 다음을 반려 사유로 발행할 수 있다:
  1. Gherkin 인수조건 0개인 설계로 출발한 티켓
  2. `Then`을 명령 1줄로 검증할 수 없는 인수조건
  3. 테스트 동반 없는 구현 커밋
- 반려 시 티켓은 '구현'으로 복귀하며, 반려 사유 1줄을 티켓에 기록한다.
- 감사봇은 판정만 발행(지휘선 아님) — report-guideline-v1.md §3 준수.
