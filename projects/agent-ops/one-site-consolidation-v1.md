# 원사이트 통합 투트랙 v1

> 이사님 09-06 지시: "원사이트로 합치는거 빨리 — 8GB 정리 전제. 스프링 부트로. 홈에 덕지덕지
> 연결된 걸 모바일·PC(추후 앱)에서 쓰게 디자인 다시 뽑아라. 레거시 정합성과 신규 정합성 투트랙."
> 매니저 역할: 현황 조사·진행률 관리·분배(구현은 위치별 봇).

## 목표

- 흩어진 포트 사이트들(현재 16+)을 **Spring Boot 원사이트 하나**로 통합 — matrix-studio-spring
  (8024, React 동서빙 실측됨)이 그 뼈대. React shell 반응형(모바일 퍼스트 + PC), 추후 앱 = 같은 API 재사용.
- 완성되면 AWS 8GB 셧다운(엣지 512MB + 홈으로 최종 정리).

## 트랙 A — 레거시 정합성 체크 (홈에 이미 배포된 것)

- 대상: 홈 GM 리눅스 8018 MATRIX 홈·8021 스튜디오·8022 넥서스 + 허브 사이트맵이 가리키는 전 링크.
- 체크: 각 링크가 ①AWS 공인 IP 의존(8GB 셧다운 시 사망) ②홈 조직망 로컬 가능 ③죽은 링크 —
  3분류 목록화. 담당: **gmwin claude**(GM 윈도우, 홈망+공인망 둘 다 도달 가능).
- 산출: 링크 정합성 목록 → notes `projects/agent-ops/legacy-link-audit-2026-09.md`.

## 트랙 B — 신규 원사이트 (스프링 부트)

- 화면 구조(IA) 초안 — 매니저 작성, zcode(SE 정본)가 상세 설계로 발전:
  - 경로 기반 통합(포트 난립 제거): `/`(홈) · `/game`(RPG·아케이드) · `/studio`(스튜디오·넥서스) ·
    `/assets`(시나리오·이미지·워크벤치) · `/daily`(뮤비 일상) · `/control`(회의방·대시보드 — 이사님 전용) · `/approve`(승인).
  - 반응형 원칙: 모바일 퍼스트 카드형, PC 그리드. PWA 준비(앱 = 동일 API).
  - 반응형/성능 기준: react-best-practices 스킬 + AGENTS.md 압축 인덱스(설계 §3).
  - 데이터: provenance 6필드 표준 연계(firebat 초안 진행 중).
- 구현: **firebat**(matrix-studio-spring 소유) — 모듈화(Modulith)와 함께 기능 단위 흡수.
- 검수: 감사(codex×claude 교차).
