# QA 파이프라인 실행 계획 v1 (RELAY-65 하부 — 이사님 10-01 승인)

> 원천: 이사님 10-01 제시 품질보증 체계(Alex Rusin 정리) — 5단계 에이전트·프롬프트 최소·도구 사후검사.
> 지위: RELAY-65(AI 개발 개선사항 전사 적용)의 실행 세부. 별도 규칙 체계 아님.

## 1. 단계별 적용 (역할 매핑 — 봇 신설 없음)
| 단계 | 담당 | 도구 | 게이트 수치 |
|---|---|---|---|
| SPECIFIER — 인수조건 | 매니저+zcode (설계 단계) | Gherkin(Given/When/Then) | 코드 티켓은 인수조건 ≥1개 없으면 설계승인 불가 |
| Coder — 테스트+구현 | 각 담당봇 | pytest / JUnit | 커밋에 테스트 동반 (무테스트 구현 반려) |
| Cleaner — CRAP | 감사봇 | pytest-cov + radon(파이썬) / JaCoCo+checkstyle(자바) | 커버리지 80%+ / 복잡도 경보(radon grade C 이하) |
| Hardener — 뮤테이션 | 감사봇 | mutmut(파) / PIT(자바) | 뮤테이션 점수 70%+ — **대형 티켓(kind:코드+대형)만** |
| QA — 실행 검증 | 테스터봇(97) | QA문서→실행스크립트 | 2xx/3xx만 통과(404 통과 금지=G2수리 후) |

## 2. 적용 범위
- 태그 `kind:코드` 티켓만 전체 파이프라인. 운영·설정 티켓은 현행 게이트 유지.
- 디스패처 발령문에 인수조건·테스트 의무 1줄 포함.

## 3. 순서 (엄수)
1. G2 테스터 버그 수리(티켓 154) — 안 고치면 QA 게이트 허위
2. 작성표준 v3 — 코드 티켓에 Gherkin 인수조건 필수화 (감사 반려 조항)
3. 감사봇 도구장착 — 커버리지·복잡도 측정 후 게이트 수치 단계 적용(먼저 측정-only 1주 → 경보 → 강제)
4. 뮤테이션 — 대형 티켓 한정 시범

## 4. 기존 티켓과 관계
- RELAY-37(게이트 테스트 커버리지 명세) → 본 계획 3단계에 흡수·종결
- G1(카드 중복억제)·G3(잠금)은 본 계획 전 수리 전제(진행 별도)

## 5. 검증
- 시범 티켓 1건(코드)으로 전 파이프라인 통과 실측 → 이사님 승인 → 전사
